Guitar FEM + STK Project — Working Summary for ChatGPT
(Keep this file inside the repo and paste it at the start of every new chat about the project)

1) Vision / Goal

Build a software tool that lets a user “design” a guitar (shape, dimensions, materials) and then:

Run a numerical physics model (FEM) to estimate physical behavior (natural frequencies / modes; later also mode shapes).

Use an audio synthesis engine (STK / C++) to generate a synthetic sound reflecting the guitar body characteristics.

Pipeline:
User input → Geometry + materials → Python FEM → modal results (JSON) → C++ STK → WAV audio

2) Environment / Setup (IMPORTANT)

Entire project runs inside an Ubuntu VM (VirtualBox), user: vboxuser, project path: ~/final-project

Development via VS Code inside the VM

Python virtual environment: .venv

STK installed in VM:

Headers: /home/vboxuser/stk/include

Libraries: /home/vboxuser/stk/build

VM Audio Note (IMPORTANT)

Audio playback inside the VM stutters/underruns; WAV files themselves are correct.

Playing the exported WAV in Windows host is smooth.

Recommended: write/export WAV output to a VirtualBox shared folder and play in Windows.

Ubuntu VM quality-of-life fixes (suggested):

Enable VirtualBox “Auto-resize Guest Display”

Install guest additions packages:

virtualbox-guest-utils, virtualbox-guest-x11, virtualbox-guest-dkms

Disable Ubuntu screen lock / blank screen to avoid resizing issues after unlock.

5) STK Side (C++) — Current Status

File: cpp/guitar_stk.cpp builds to ./guitar_stk

Current synthesis model:

Requires a musical pitch (note) AND optionally applies body coloration using FEM modes_hz from a JSON result file.

Deterministic playback mode (Option A) was used to eliminate unstable random variation.

Parameter input via CLI flags (used by python/run.py).

Key idea:

Musical note frequency defines “what note is played”

FEM modes define “body timbre / coloration”

7) Key Audio Finding (IMPORTANT)

Even when WAV outputs are correct and deterministic, all three woods currently sound almost identical.

Conclusion:

Differences in modal frequencies alone are not enough with the current simplified model.

The missing ingredients for audible material differences are:

Mode weights (how strongly each body mode is excited / contributes)

Damping / Q (decay per mode; currently simple/constant)

Next major audio upgrades (planned)

Add mode_weights to FEM output JSON (derived from mode shapes and an excitation point/area, e.g., “bridge point”).

Improve Q modeling:

short-term: constant Q per wood (config-driven)

later: Q per mode / Rayleigh damping / calibrated ranges from literature

Later: add “controlled liveliness” (Option B) with a stable seed and bounded variation.

Note:

skip: 1 in STK runs may hide the lowest mode differences; for testing, try skip: 0.
